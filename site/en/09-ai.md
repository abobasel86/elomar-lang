# 9. AI in the language

In Elomar-Lang, asking a model is a normal, typed function call. You say
what type you want back, and the language checks the model's answer before
your program sees it.

## A first AI call, offline

The built-in model `mock` needs no account and costs nothing, which is
ideal for learning and tests:

```elomar
use std.ai

type Summary = { title: String, points: List<String> }

async fn main() {
    match await ai.infer<Summary>(
        model: "mock",
        instructions: "Summarize the text in a title and short points",
        input: "Elomar-Lang is a typed language with AI built in."
    ) {
        Ok(s) => print("title: {s.title}, points: {s.points.length}")
        Err(e) => print("failed: {e.kind()}")
    }
}
```

What is new here:

- `async fn main` and `await`: an AI call takes time, so it returns a
  *future* that you `await`.
- `ai.infer<Summary>` asks for a `Summary`. If the model answers with
  anything else, you get `Err(AIError.InvalidStructuredOutput(...))`, never
  a half-filled record.
- Errors are values of `AIError`: `Timeout`, `RateLimited`,
  `Authentication`, `PolicyDenied`, and others. Match on them like any enum.

## Start a project in one command

```bash
elomar new helpdesk --ai ollama      # or mock, openai, anthropic
cd helpdesk
elomar doctor                        # checks keys, permissions and models
elomar run src/main.elo
```

`elomar new --ai` writes `elomar.toml` for the provider you choose, a
module that calls a model, and tests that pass offline. `elomar doctor`
tells you what is missing before you run: a key that is not set, a host
that is not allowed, a server that is not running, or a model id the
provider does not have.

## A real model

Describe the model in `elomar.toml` and give it a name your code uses:

```toml
[ai.models."support.classifier"]
provider = "anthropic"             # or "openai"
model = "claude-opus-5-5"
api_key_env = "ANTHROPIC_API_KEY"  # the key stays in the environment

[ai.policy]
max_calls_per_run = 20

[permissions]
network_hosts = ["api.anthropic.com"]
```

```elomar
use std.ai

enum Priority { Low, Normal, Urgent }
type Ticket = { category: String, priority: Priority, summary: String }

pub async fn classify(text: String) -> Result<Ticket, AIError> !{ai, net} {
    return await ai.infer<Ticket>(
        model: "support.classifier",
        instructions: "Classify the support request.",
        input: text,
        timeout: 30s
    )
}

async fn main() {
    match await classify("I was charged twice for my order!") {
        Ok(t) => print("[{t.priority}] {t.category}: {t.summary}")
        Err(e) => print("AI failed ({e.kind()}): {e.message()}")
    }
}
```

Notice `!{ai, net}`: a public function that calls a cloud model must say
so. Anyone reading `classify` knows it uses AI and the network.

Safety is built in: the key is read from the environment and never shown in
messages, only listed hosts can be reached, and the call budget stops a
runaway loop. Your `input` is sent as data, and the model is told not to
follow instructions inside it.

Each person who runs your program uses their own key: set it in your own
terminal before running (`$env:ANTHROPIC_API_KEY = "..."` in PowerShell,
`export ANTHROPIC_API_KEY=...` elsewhere). Nothing in `elomar.toml` or your
code holds a key, so sharing a project never shares one. HTTPS also trusts
the certificates your system trusts, so calls work behind antivirus programs
and company proxies that inspect secure connections. If the vendor rejects
the model id, the error says to check `model` in `elomar.toml`.

## A free model on your computer

[Ollama](https://ollama.com) runs open models on your own computer, with
no key and no cost per call. Install it, pull a model
(`ollama pull qwen2.5:7b`, and `ollama pull nomic-embed-text` for
embeddings), then point a model at it:

```toml
[ai.models.local]
provider = "openai"
model = "qwen2.5:7b"
base_url = "http://localhost:11434/v1"

[permissions]
network_hosts = ["localhost:11434"]
```

Your code does not change: `ai.infer<Ticket>("local", ...)`, `ai.stream`
and `ai.search` work the same. No key is needed for a server on
`localhost`. See [`examples/ai-local`](https://github.com/abobasel86/elomar-lang/tree/main/examples/ai-local).

## Many requests at once

`await all([...])` waits for several AI calls and returns their results in
order. Calls passed directly are sent at the same time, so ten requests
take about as long as one:

```elomar
use std.ai

async fn main() {
    let texts = ["I love it", "It broke", "Fine"]
    let answers = await all(texts.map(|t| ai.infer<String>("mock", "Classify the mood", t)))
    for item in texts.enumerate() {
        print(item.value, answers[item.index])
    }
}
```

Each call still passes the permission and budget checks, and each answer
is its own `Result`, so one failure does not hide the others.

## Answers as they are written: `ai.stream`

`ai.stream` gives the answer piece by piece as the model writes it, so a
long answer can be shown at once instead of after it is complete. The
function you pass gets each piece; the result is the whole text:

```elomar
use std.ai

async fn main() {
    let story = await ai.stream("mock", "Tell a short story.", "a cat and the sea", |piece| {
        print(piece)
    })
    match story {
        Ok(text) => print("{text.length} characters in all")
        Err(e) => print("failed: {e.message()}")
    }
}
```

OpenAI and Claude models stream for real. The mock model streams its
answer one word at a time.

## Meaning as numbers: `ai.embed`

`ai.embed` turns a text into a list of numbers, an *embedding*, whose
direction stands for the text's meaning. `ai.similarity` compares two:
1 means the same direction, 0 unrelated. This is how to search by meaning
instead of by exact words:

```elomar
use std.ai

async fn main() {
    let notes = ["feeding the cat", "paying the electricity bill", "the cat sleeps on the mat"]
    var vectors: List<List<Float>> = []
    for n in notes {
        match await ai.embed("mock", n) {
            Ok(v) => vectors.push(v)
            Err(e) => print(e.message())
        }
    }
    match await ai.embed("mock", "where the cat sleeps") {
        Ok(q) => {
            let scores = vectors.par_map(|v| ai.similarity(q, v))
            print(scores.map(|s| s.round_to(2)))   // [0.58, 0.25, 0.71]
        }
        Err(e) => print(e.message())
    }
}
```

The mock model compares words, so it works offline in tests. A real
embedding model (`provider = "openai"` with a model such as
`text-embedding-3-small`) also understands synonyms and other languages.
Claude models do not make embeddings: `ai.embed` on one fails with
`UnsupportedCapability`. `ai.similarity` is plain arithmetic, so it runs
inside `par_` methods on every core.

To embed many texts, wait for them together: `await all` sends the calls
to each model at once, and an OpenAI model embeds up to 256 texts in one
request:

```elomar
use std.ai

async fn main() {
    let notes = ["feeding the cat", "paying the bill", "the cat sleeps"]
    let vectors = await all(notes.map(|n| ai.embed("mock", n)))
    print(vectors.count(|r| r.is_ok()))   // 3
}
```

`ai.search` does all of this in one call: it embeds the question and the
texts together and returns the texts with their scores, closest first:

```elomar
use std.ai

async fn main() {
    let notes = ["feeding the cat", "paying the electricity bill", "the cat sleeps on the mat"]
    match await ai.search("mock", "where the cat sleeps", notes) {
        Ok(hits) => {
            for h in hits.take(2) {
                print(h.text, h.score.round_to(2))
            }
            // the cat sleeps on the mat 0.71
            // feeding the cat 0.58
        }
        Err(e) => print(e.message())
    }
}
```

Searching the same notes again and again? Keep their vectors in a file,
and a text already embedded is never sent again:

```toml
[ai.cache]
embeddings = "embeddings.cache.json"
```

## Tools: let the model call your functions

With `ai.run`, the model may call the functions you list, and only those:

```elomar
use std.ai

type Student = { name: String, grade: Int }
type Answer = { answer: String }

let STUDENTS = [{ name: "Lina", grade: 91 }, { name: "Omar", grade: 55 }]

fn find_student(name: String) -> Option<Student> {
    return STUDENTS.find(|s| s.name == name)
}

async fn main() {
    match await ai.run<Answer>(
        model: "mock",
        instructions: "Answer questions about the class using the tools.",
        input: "What is Lina's grade?",
        tools: [find_student],
        max_steps: 5
    ) {
        Ok(a) => print(a.answer)
        Err(e) => print(e.kind())
    }
}
```

The types of `find_student` become the description the model sees, and its
arguments are checked before your function runs.

## Agents with MCP tools and approvals

`agent.run` adds tools from MCP servers (listed in `elomar.toml`), a code
function that approves risky actions, and a log of every step:

```text
agent.run<Answer>(
    model: "assistant",
    instructions: "Keep my notes tidy.",
    input: request,
    mcp: ["notes"],
    require_approval: ["notes.delete_all"],
    approve: |call| ask_user(call.tool),
    on_step: |step| print("step: {step.tool} approved={step.approved}")
)
```

The decision to allow a dangerous action is made by your code, not by the
text of a prompt. See
[`examples/agents`](https://github.com/abobasel86/elomar-lang/tree/main/examples/agents).
