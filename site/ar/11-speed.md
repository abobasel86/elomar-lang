# 11. السرعة والتوازي

أغلب البرامج سريعة دون أي جهد منك: يحوّل `elomar` كل دالة إلى شيفرة بايت (bytecode) أول مرة تُستدعى، ثم يشغّلها في
محرك سريع. يشرح هذا الدرس كيف تستخدم **كل أنوية** المعالج، وكيف تكتب شيفرة تبقى سريعة مهما كبرت البيانات.

## قاعدة واحدة لكل القوائم: `par_`

دالة القائمة التي يبدأ اسمها بـ`par_` تعطي **تمامًا** ما تعطيه الدالة نفسها بلا `par_`، لكنها تقسّم القائمة أجزاءً
وتنفذ الدالة على عدة أنوية معًا:

```elomar
fn الخطوات(n: Int) -> Int {
    var x = n
    var العدد = 0
    while x != 1 {
        if x % 2 == 0 {
            x = x div 2
        } else {
            x = 3 * x + 1
        }
        العدد += 1
    }
    return العدد
}

fn main() {
    var الأعداد: List<Int> = []
    for i in 1..=100000 {
        الأعداد.push(i)
    }
    print(الأعداد.par_map(الخطوات).take(5))          // [0, 1, 7, 2, 5]
    print(الأعداد.par_count(|n| الخطوات(n) > 200))   // 4001
    print(الأعداد.par_max_by(الخطوات))               // Some(77031)
    print(الأعداد.par_find(|n| الخطوات(n) > 300))    // Some(26623)
    print(الأعداد.par_sum_by(الخطوات))               // 10753840
}
```

على حاسوب بثماني أنوية، كل سطر من هذه أسرع بخمس إلى تسع مرات من `map` و`count` و`max_by` و`find` و`sum_by`.

| الدالة | تعطي ما تعطيه |
|---|---|
| `par_map(f)` | `map(f)` |
| `par_filter(f)` | `filter(f)` |
| `par_count(f)` | `count(f)` |
| `par_any(f)` / `par_all(f)` | `any(f)` / `all(f)` |
| `par_find(f)` | `find(f)` |
| `par_sort_by(f)` | `sort_by(f)` (والترتيب مستقر) |
| `par_min_by(f)` / `par_max_by(f)` | `min_by(f)` / `max_by(f)` |
| `par_sum_by(f)` | `sum_by(f)` |
| `par_flat_map(f)` | `flat_map(f)` |
| `par_group_by(f)` | `group_by(f)` |
| `par_fold(init, f)` | `fold(init, f)` إن كانت `f` تجميعية (انظر أدناه) |

النتيجة واحدة في كل الحالات: الترتيب نفسه والعناصر نفسها والخطأ نفسه. إن فشلت الدالة في عدة عناصر فالخطأ خطأ
**أولها**، كما بلا `par_`. وتُوقف `par_find` و`par_any` و`par_all` الأجزاءَ التي بعد أول جزء يجد ما تبحث عنه، فلا
يغيّر عنصر بعده النتيجة، كما أن `find` ما كانت لتصل إليه.

## القواميس والمجموعات

ليس للقواميس والمجموعات دوال `par_` خاصة بها: حوّلها إلى قائمة أولًا. تعطي `entries()` و`keys()` و`values()` قوائم
القاموس، وتعطي `to_list()` عناصر المجموعة، بالترتيب:

```elomar
fn main() {
    let الأسعار = ["tea": 4, "coffee": 7, "juice": 5]
    let الغالية = الأسعار.entries().par_filter(|e| e.value > 4).map(|e| e.key)
    print(الغالية)                                       // ["coffee", "juice"]
    print(الأسعار.keys().par_count(|k| k.length > 3))    // 2
    let المرئية = set([12, 7, 30, 9])
    print(المرئية.to_list().par_map(|n| n * 2))          // [14, 18, 24, 60]
}
```

## ما الذي يعمل على الأنوية

يذهب العمل إلى الأنوية فقط حين لا يمكن تمييزه عن تنفيذ العناصر واحدًا بعد الآخر. يجب أن تكون الدالة **معزولة**: هي
وكل دالة تستدعيها

- لا تطبع شيئًا ولا تقرأ مدخلات؛
- لا تستخدم ملفًا ولا قاعدة بيانات ولا عملية ولا Python ولا أداة MCP ولا نموذج ذكاء اصطناعي؛
- لا تستخدم أعدادًا عشوائية.

ويمكنها أن تحسب، وأن تستخدم النصوص والقوائم والقواميس والسجلات والتعدادات، والوحدات `std.math` و`std.json`
و`std.regex` و`std.time` وأمثالها. والدالة غير المعزولة تعمل أيضًا: تُنفذ الدالة عندها على العناصر واحدًا بعد الآخر
بالترتيب، فيبقى ما تطبعه بترتيبه.

```elomar
fn مزعجة(n: Int) -> Int {
    print("أعمل على {n}")
    return n * n
}

fn main() {
    print([1, 2, 3].par_map(مزعجة))   // تطبع بالترتيب، ثم [1, 4, 9]
}
```

استخدم دوال `par_` للعمل **الثقيل** على كل عنصر. أما العمل الخفيف مثل `x * 2` فتقسيم القائمة يكلّف أكثر مما يوفّر.

## الطيّ على أجزاء: `par_fold`

تقسّم `par_fold(init, f)` القائمة إلى 64 جزءًا متجاورًا على الأكثر، يحددها طول القائمة وحده، وتطوي كل جزء على نواة،
ثم تطوي نتائج الأجزاء معًا بـ`f`. لذا تأخذ `f` عنصرين وتعيد عنصرًا من النوع نفسه. وحين تعطي `f` النتيجة نفسها كيفما
جُمّعت العناصر، كالجمع و`max` ووصل النصوص، تكون النتيجة نتيجة `fold`:

```elomar
fn main() {
    let الكلمات = ["one", "two", "three", "four"]
    print(الكلمات.par_fold("", |a, b| a + b))     // onetwothreefour
    print([4, 9, 2].par_fold(0, |a, b| a + b))    // 15
}
```

والنتيجة واحدة على كل حاسوب، بأي عدد من الأنوية.

## عدة استدعاءات معًا: `await all`

تنتظر `await all([...])` عدة استدعاءات لدوال `async fn`. الاستدعاءات المتجاورة المعزولة تعمل على عدة أنوية في الوقت
نفسه، وتعود النتائج بترتيب القائمة:

```elomar
async fn المجموع(من: Int, إلى: Int) -> Int {
    var s = 0
    for i in من..إلى {
        s += i % 7
    }
    return s
}

async fn main() {
    let الأجزاء = await all([المجموع(0, 100000), المجموع(100000, 200000), المجموع(200000, 300000)])
    print(الأجزاء)   // [299995, 299999, 300003]
}
```

وتعمل استدعاءات `ai.infer` داخل `all` معًا كذلك، كما في [درس الذكاء الاصطناعي](09-ai.html).

## كتابة شيفرة سريعة

- **ابنِ النصوص والقوائم بالإضافة إليها.** تضيف `النص += قطعة` و`القائمة.push(عنصر)` في المكان نفسه حين لا تشارك
  قيمةٌ أخرى القيمةَ نفسها، فتبقى الحلقة التي تبني نصًّا كبيرًا سريعة.
- **استخدم الفهرسة في النصوص بحرية.** تتذكر `s.slice(i, i + 1)` و`s.length` أين تبدأ حروف النص الطويل، فالمرور على
  نص بالفهرس سريع، والنص العربي المشكول كذلك.
- **استخدم القواميس للبحث.** تجد `العدد[الكلمة]` المفتاح فورًا مهما كبر القاموس.
- **قِس.** تعطي `time.now()` الوقت بالميلي ثانية:

```elomar
use std.time

fn main() {
    let البداية = time.now()
    var النص = ""
    for i in 0..20000 {
        النص += "{i},"
    }
    print("{النص.length} حرفًا في {time.now() - البداية} ms")
}
```

## مفاتيح للتحقق

متغيرا بيئة يغيّران طريقة تشغيل البرامج، ولا يغيّران أبدًا ما يطبعه البرنامج:

| المتغير | عمله |
|---|---|
| `ELOMAR_PARALLEL=0` | تشغيل كل شيء على نواة واحدة، عنصرًا بعد عنصر |
| `ELOMAR_ENGINE=tree` | التشغيل في المفسّر الشجري الأبسط بدل محرك شيفرة البايت |

وكلاهما مفيد لمقارنة الأوقات، أو للتأكد من أن النتيجة لا تعتمد على الأنوية. في PowerShell:
`$env:ELOMAR_PARALLEL = "0"`؛ وفي صدفة Unix: `ELOMAR_PARALLEL=0 elomar run main.elo`.
